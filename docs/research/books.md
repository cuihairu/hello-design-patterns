# 权威书籍与标准目录调研

按书拆条目，逐本对照站内覆盖。"已覆盖"指站内有正文页，"部分"指站内有相邻篇目但口径或角度不同，"缺口"指没有对应页。逐条差异与处置见[覆盖核对与差异表](/research/coverage)。

## 设计模式（GoF，1994）[S1]

23 个模式，创建型 5、结构型 7、行为型 11，是本仓的基准线。

| 分类 | 模式 | 站内 |
| --- | --- | --- |
| 创建型（5） | 抽象工厂、建造者、工厂方法、原型、单例 | 5/5 全部有页 |
| 结构型（7） | 适配器、桥接、组合、装饰、外观、享元、代理 | 7/7 全部有页 |
| 行为型（11） | 责任链、命令、解释器、迭代器、中介者、备忘录、观察者、状态、策略、模板方法、访问者 | 11/11 全部有页 |

GoF 之外，站内还收了它没有的条目：多例、对象池、服务定位器（创建型），动态代理、保护代理、远程代理、虚拟代理、智能指针、双向桥接、依赖注入（结构型），回调、DSL、快照（行为型），以及并发与特定领域两个目录。

## Head First 设计模式（第 2 版，2020）[S2]

案例书，模式比 GoF 少但讲解顺序按"先解决一个问题"排。它的目录全部落在站内已有的策略、观察者、命令、适配器与外观、模板方法、迭代器与组合、状态、单例、装饰、工厂方法、抽象工厂、代理这些篇里。

这本书给本仓带来两个额外要求：

1. 它在观察者一章讲开闭原则，第 2 版还加了 Lambda 与函数式接口的写法。站内没有专门讲开闭原则与 SOLID 的篇目，本次补在[现代演进导读](/evolution/overview)下的[SOLID 与依赖规则](/evolution/solid)。
2. 它明确讨论单例的代价（全局状态、测试困难、序列化与反射破坏），站内[单例模式](/creational/singleton)有实现细节，缺反面视角，由[神对象](/anti-patterns/god-object)与[金锤子](/anti-patterns/golden-hammer)承接。

## 架构整洁之道（Clean Architecture，2017）[S3]

三块内容与站内对应关系：

- SOLID 五原则 → 本次新增[组合式设计](/evolution/composition-over-inheritance)与[SOLID 与依赖规则](/evolution/solid)；
- 依赖规则与层级划分（实体、用例、接口适配器、框架与驱动）→ 站内没有架构分层篇，本次不展开，只在 SOLID 篇里讲依赖方向；
- 组件级三原则（复用与使用等价、稳定依赖、无环依赖）→ 同上，列在 SOLID 篇的延伸阅读里，暂不单独成篇。

SOLID 的更早出处是 Martin 2002 年那本书 [S4]，两本口径一致。

## 企业应用架构模式（P of EAA，2002）[S5]

这本书的目录分领域逻辑、数据源架构、Web 表现层、分布、并发与事务几组。逐项核对：

- 领域逻辑四式（事务脚本、领域模型、表模块、活动记录）：站内只有[ORM](/other/orm)里顺带提到活动记录与数据映射器，事务脚本在[设计模式概览](/introduction)里列了但没有页。本次新增[事务脚本](/other/transaction-script)，并与[贫血模型](/anti-patterns/anemic-domain-model)对照。
- 数据源四式（表网关、行数据网关、活动记录、数据映射器）：由 ORM 篇覆盖，不单独成篇。
- 仓储与单元工作：站内没有，仓储与 DDD 的仓储同源 [S11]，本次不新增，列在差异表"暂不收录"，理由是与 ORM 篇的边界要先划清。
- Web 表现层（前端控制器、页面控制器、模板视图）：MVC 篇部分覆盖，前端控制器缺，本次不新增。
- 远程外观与数据传输对象：与站内[远程代理](/structural/remote-proxy)角度不同，前者面向服务边界，后者面向对象访问，本次不新增，记入差异表。

## 重构（第 2 版，2018）[S6]

坏味道目录（过长函数、过大的类、依恋情节、数据泥团、霰弹式修改等）是反模式篇的代码层依据。站内原本一条坏味道都没有，本次用[反模式导读](/anti-patterns/overview)把"坏味道—反模式—模式"三层关系讲清，具体坏味道的演进路径引 Joshua Kerievky 的《Refactoring to Patterns》[S14]，站内不逐条复制原书目录。

## 面向模式的软件架构（POSA，卷 1 与卷 2）[S9]

- 卷 1 的分层、管道-过滤器、黑板、代理：站内有[代理](/structural/proxy)，分层与管道-过滤器没有篇目，本次不新增，列入差异表"暂不收录"，理由是这两条偏架构风格，需要先给"架构风格与模式的边界"一个说法。
- 卷 2 的反应器、主动器、主动对象、生产者-消费者、半同步/半异步：站内前四条都有页，半同步/半异步与[主动对象](/concurrency/active-object)接近，本次不新增。

## 企业集成模式（EIP，2002）[S10]

消息通道、消息路由器、消息转换器、发布订阅等条目，站内由[观察者](/behavioral/observer)、[中介者](/behavioral/mediator)、[责任链](/behavioral/chain-of-responsibility)覆盖了"通知与分发"的近似场景，但缺少消息管道与路由的独立篇目。本次不新增，记入差异表，理由是需要先决定本仓是否开"集成模式"分区。

## 领域驱动设计（DDD，2003）[S11]

聚合、仓储、规格、限界上下文：站内一条都没有。仓储与规格本次不新增（与 ORM 篇边界未划清），聚合与限界上下文属于战略设计，不在本仓"模式"口径内，两者都记入差异表"暂不收录"并写明理由。

## Release It!（第 2 版，2018）[S12]

稳定性模式中，站内一条都没有。熔断器应用面最广（限流、降级、故障隔离三个场景都用它），本次新增[熔断器](/evolution/circuit-breaker)。隔舱、超时、重试、稳态列入差异表"暂不收录"，后续可与熔断器同批补。

## 微服务与容器 [S13][S15]

API 网关、服务发现、Saga、断路器 vs 熔断、Sidecar、声明式 API：站内只有[事件溯源](/other/event-sourcing)与 Saga 相关的叙述。这两本书的目录作为后续选题来源记录在差异表，本次不新增。
