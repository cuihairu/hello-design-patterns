# 行为型模式 (Behavioral Patterns)

**主要解决的问题**：对象之间如何协作和职责分配。这类模式关注算法、职责分配和对象之间的通信。
行为型模式关注对象之间的职责分配与通信方式，常见的手段包括把算法封装成可替换的对象、把请求封装成对象、以及在对象之间引入中介或观察关系，从而降低对象之间的耦合。

### 本目录包含的模式

- [策略模式](/behavioral/strategy)：定义一系列可互换的算法，使算法的变化独立于使用它的客户端。
- [观察者模式](/behavioral/observer)：建立一对多的依赖关系，状态变化时自动通知所有观察者。
- [命令模式](/behavioral/command)：把请求封装成对象，支持参数化、排队、日志与撤销。
- [责任链模式](/behavioral/chain-of-responsibility)：让多个对象都有机会处理请求，沿链传递直到被处理。
- [中介者模式](/behavioral/mediator)：用中介对象封装一组对象之间的交互，避免对象直接相互引用。
- [迭代器模式](/behavioral/iterator)：顺序访问聚合对象中的元素，而不暴露其内部表示。
- [模板方法模式](/behavioral/template-method)：定义算法骨架，把某些步骤延迟到子类实现。
- [状态模式](/behavioral/state)：对象在内部状态改变时改变自己的行为。
- [备忘录模式](/behavioral/memento)：在不破坏封装性的前提下保存并恢复对象的内部状态。
- [快照模式](/behavioral/snapshot)：备忘录模式的另一种常见叫法，侧重快照的创建与恢复。
- [解释器模式](/behavioral/interpreter)：为简单语言定义文法表示，并提供解释句子的解释器。
- [访问者模式](/behavioral/visitor)：在不改变元素类的前提下，为对象结构增加新的操作。
- [回调模式](/behavioral/callback)：把处理逻辑作为回调传入，在异步操作完成或事件发生时被调用。
- [领域特定语言（DSL）](/behavioral/dsl)：针对特定领域设计专用语言或语言扩展，提高表达效率。

### 选用建议

- 算法需要可替换时用策略；行为随状态变化时用状态。
- 一对多的状态通知用观察者；请求的处理者不确定时用责任链。
- 需要撤销、排队、记录日志的请求用命令；需要保存历史状态用备忘录。
- 遍历逻辑与容器实现分离用迭代器；稳定结构上频繁新增操作用访问者。
