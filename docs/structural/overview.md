# 结构型模式 (Structural Patterns)

**主要解决的问题**：类和对象的组合方式。这类模式通过不同方式组合对象，以形成更大的结构。
结构型模式关注如何把类和对象组合成更大的结构，同时保持结构的灵活与高效。它们主要通过继承与组合两种手段，在不改变现有代码的前提下为系统增加新的能力。

### 本目录包含的模式

- [适配器模式](/structural/adapter)：把一个类的接口转换成客户端期望的另一个接口，使原本不兼容的类可以协同工作。
- [装饰模式](/structural/decorator)：动态地为对象添加职责，而不改变其接口。
- [代理模式](/structural/proxy)：为其他对象提供代理以控制对它的访问。
- [虚拟代理模式](/structural/virtual-proxy)：延迟创建开销大的对象，直到真正需要时才实例化。
- [保护代理模式](/structural/protection-proxy)：根据访问权限控制对真实对象的访问。
- [远程代理模式](/structural/remote-proxy)：为不同地址空间中的对象提供本地代表，隐藏远程通信细节。
- [动态代理模式](/structural/dynamic-proxy)：在运行时生成代理类，统一处理日志、事务等横切关注点。
- [智能指针模式](/structural/smart-pointer)：以智能指针的形式在访问对象时附加额外操作，并自动管理资源。
- [外观模式](/structural/facade)：为子系统中的一组接口提供一个统一的高层接口，简化子系统的使用。
- [远程外观与数据传输对象](/structural/remote-facade)：跨进程边界不放领域对象，放按用例切分的粗粒度接口与专用传输对象。
- [桥接模式](/structural/bridge)：将抽象部分与实现部分分离，使二者可以独立变化。
- [双向桥接模式](/structural/bidirectional-bridge)：在桥接的基础上支持两个层次结构之间的双向通信。
- [组合模式](/structural/composite)：将对象组合成树形结构表示"部分-整体"的层次，使客户端一致地使用单个对象与组合对象。
- [享元模式](/structural/flyweight)：通过共享细粒度对象来支持大量对象，减少内存占用。
- [依赖注入](/structural/dependency-injection)：由外部容器提供对象所需的依赖，实现对象之间的解耦。

### 选用建议

- 接口不兼容时用适配器；接口太复杂时用外观；接口要跨进程时用远程外观加 DTO，别把细粒度对象接口摆上网络。
- 需要控制访问、延迟加载或附加额外行为时，选择代理及其变体。
- 需要动态叠加行为时用装饰，而不是创建大量子类。
- 存在多个独立变化维度时用桥接；存在大量相似对象时考虑享元。
